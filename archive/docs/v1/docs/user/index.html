User Guide

Learn how to pass data dictionaries, structure element blueprints, and safely interpolate dynamic values.

1. The Function Contract

Using ES Modules:

import applyTemplate from "json-transformer-funcs-primitive";

const resolved = applyTemplate(inElement, inTemplate, showLog);

Or via the Global Tree:

// 1. Direct top-level access
const resolved = window.ks.applyTemplate(inElement, inTemplate, showLog);

// 2. Family tree access
const resolved = window.ks.transformerFuncs.primitive.applyTemplate(inElement, inTemplate, showLog);
Argument Type Obligation Description
inElement Plain Object Required A key-value dictionary used to replace matching ${key} tokens.
inTemplate Object | String Required The JSON-to-DOM AST node or string template containing ${placeholder} slots.
showLog Boolean Optional When true, outputs debugging telemetry to console.log.

2. Guard Rails & Fail-Fast Exceptions

The primitive engine enforces strict boundary validation before any execution occurs. If invalid types are supplied, it halts immediately with a clear error:

Input Condition Error Thrown Design Rationale
inTemplate is null or undefined TypeError: inTemplate is undefined or null Prevents silent no-ops when templates fail to load from server.
inTemplate is not an Object or String TypeError: inTemplate is not an object or string Guarantees that only valid JSON AST nodes or string templates enter the pipeline.
inElement is an Array TypeError: inElement is an array Enforces the 0D/Atom boundary. Array mapping belongs to 1D (one-dimension).
inElement is not an Object TypeError: inElement is not an object Tokens can only be resolved against structured key-value dictionaries.

3. Immutability & Zero Side-Effects

A core tenet of the engine is 100% AST Immutability. Internally, structuredClone(inTemplate) creates a pristine clone before any token resolution begins.

  • The original inTemplate is never mutated in memory.
  • You can safely cache, reuse, and share template definitions across thousands of calls without contamination.

4. KeshavSoft Coding Conventions

All KeshavSoft modules follow a strict variable naming standard:

  • in prefix: Parameters entering a function (e.g. inElement, inTemplate).
  • local prefix: Variables scoped inside the function body (e.g. localElement, localClonedTemplate).
